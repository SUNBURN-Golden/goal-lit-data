# 꼴릿 데이터 기반이 답해야 할 대표 질문

꼴릿은 억지로 "디지털트윈"이라 부르지 않는다. **문학 지식그래프(근거 그래프)** 이고,
실제로 *상태가 바뀌는 대상*은 두 가지뿐이다: ① 출처 문서(내용이 바뀌거나 사라짐), ② 서지 사실·판본 정보(정정·상충).
이 두 가지에 대해서만 상태 이력을 추적하고, 나머지는 근거 그래프로 둔다.

공통 답변 규칙 (모든 질문):
1. 답의 모든 항목에 `출처 URL + 근거 위치 + collected_at + 확인 수준(확인된 사실 / 출처의 주장 / AI 추론 / 미확인)`을 붙인다.
2. 서지 사실과 해석은 **다른 칸**에 보여준다. AI 추론은 항상 별도 칸이며 사실 칸에 섞지 않는다.
3. 근거를 못 찾았으면 "없음"이 아니라 **"확인하지 못함"** 으로 답한다. (조건을 못 찾았다고 빈 값을 사실로 처리하지 않는다.)
4. 상충하는 답은 하나를 고르지 않고 **둘 다 작성자·근거와 함께** 보여준다.
5. 인용은 12자 이하, 어떤 문장도 출처와 15자 이상 겹치지 않는다. 근거는 "위치"로 가리킨다.

## Q1. 이 작품의 판본(원전·번역본·개정판·연재본/단행본)은 무엇이고, 판본끼리 무엇이 다른가?
- 필요한 개체: Work → Edition(출판사·번역자·언어·연도·ISBN·쪽수) → Source
- 시간: 판본별 `valid_from`(출간 시점, 모르면 NULL — "항상"으로 채우지 않는다), 정정 이력
- 검증 규칙: 같은 ISBN이면 같은 판본, ISBN이 없으면 `provisional` 판본으로 따로 보관하고 합치지 않는다.
- 답 형식: 판본 목록 + 속성별 비교표(값, 출처, 확인 수준). 값이 다른 속성은 `상충`으로 표시.
- 못 답하는 경우: 판본이 1개뿐이거나 속성 근거가 없으면 "비교할 판본 정보 부족"과 부족 속성 목록을 낸다.

## Q2. 이 주제(Theme)에 대해 서로 반대되는 해석·비평은 무엇이고, 각각 누가 어떤 근거 위치에서 말했나?
- 필요한 개체: Theme ← Interpretation(작성자·입장·요약) → EvidencePassage(위치만) → Source
- 관계: `opposes`는 **출처가 반론임을 명시했거나 편집자가 확정한 경우만** 확정. AI가 제안한 반대 관계는 `ai_inference`로 따로.
- 시간: 해석이 발표된 시점(`valid_from`), 작성자의 입장 변경은 새 행으로 추가.
- 답 형식: 입장별 묶음(작성자, 출처, 근거 위치, 확인 수준) + 아직 반론이 짝지어지지 않은 해석 목록.

## Q3. 이 작가는 이 작품에 대해 무엇을 말했고, 그 발언의 출처·시점·맥락은?
- 필요한 개체: Author → AuthorStatement(발언 시점·매체·맥락) → EvidencePassage → Source
- 검증 규칙: 발언의 출처가 1차(인터뷰 원문·작가의 말)인지 2차(기사가 전한 발언)인지 `source_access_level`로 구분. 원 출처 URL이 없으면 `출처의 주장`까지만, 확인 큐에 올린다.
- 시간: 발언 시점(`valid_from`)과 수집 시점(`collected_at`)을 분리.

## Q4. 이 작품의 수상·출간·연재 같은 서지 사실은 무엇이고, 어디까지 확인됐나?
- 필요한 개체: Work/Edition → BibliographicFact(predicate, value) → Source
- 답 형식: 사실별 확인 수준(확인된 사실 / 출처의 주장 / 미확인) + 아직 확인 못한 항목(예: 초판 출간일, 누적 판매 부수)을 **미확인으로 명시**.
- 검증 규칙: 확인된 사실로 올리려면 ① 외부 출처 URL ② 근거 위치 ③ 수집 시각 ④ 충돌 없음, 4가지를 모두 만족해야 한다.

## Q5. 출처끼리 충돌하거나 정정된 정보는 무엇이고, 지금 검수 대기 중인 것은?
- 필요한 개체: Conflict, CorrectionHistory, ReviewQueue
- 규칙: 충돌·정정은 덮어쓰지 않는다. 이전 값은 `valid_to`를 닫아 보존하고, 새 값을 추가한다. 충돌 해소 전에는 `publish_pending` 승격 차단.
- 답 형식: 충돌쌍(양쪽 값·출처), 정정 타임라인, 검수 대기 목록(우선순위·사유).

## Q6. 이 작품에 대해 우리가 아직 모르는 것(미확인)과 "AI가 제안만 한 것"은 무엇인가?
- 필요한 개체: `unverified` 상태 행, AiInference
- 규칙: AI 추론은 별도 테이블. 사람이 근거를 붙여 새 주장 행으로 승격하기 전에는 어떤 질문의 "확정" 답에도 나오지 않는다.
- 답 형식: 미확인 항목(서지/발언/작품 해석 3분류) + AI 제안 목록(승격 대기).

## Q7. 이 작가의 작품들이 공통으로 다루는 주제는 무엇이고, 어떤 출처가 그렇게 말하나?
- 필요한 개체: Author → Work → (WorkTheme: 출처가 말한 주제 연결) → Theme
- 규칙: "작가 A의 작품 X, Y에 같은 주제가 있다"는 두 연결 각각에 출처가 있을 때만 보여준다. 둘을 합쳐 "A의 일관된 주제"라고 AI가 단정하지 않는다.

## Q8. 최근 N일 사이 출처 문서가 바뀌었거나 사라졌고, 그 때문에 어떤 사실·해석이 영향을 받았나?  (상태 추적)
- 필요한 개체: SourceSnapshot(콘텐츠 해시·HTTP 상태·확인 시각) → 변경 이벤트 → 영향받는 주장
- 규칙: 내용 해시가 바뀌면 의존하는 주장들의 확인 수준을 `재검증 필요`로 표시하고 검수 큐에 올린다(삭제 아님). 출처가 사라지면 주장은 유지하되 `source_unreachable` 표시.
- 답 형식: 변경 목록(출처, 이전/이후 확인 시각), 영향받는 주장 목록, 재검증 큐.
